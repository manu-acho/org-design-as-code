# Table 1. Theoretical Constructs and Observable Indicators

**Status:** Week 6 draft based on Codebook version 1.0. Final inclusion depends on full coding and manuscript scope.

| Construct family | Core analytical object | Observable reference indicators | Exclusion or boundary |
|---|---|---|---|
| Organisation design | Division and integration of work | Roles, actions, structural units, handoffs, shared objects, information relations | Reference design is not customer structure or fit |
| Interdependence | Relation among differentiated activities | Prerequisite state, shared governed resource, or reciprocal adjustment | Temporal order and shared platform are insufficient alone |
| Coordination | Mechanism addressing an identified dependency | Standardised work or output, planning, supervision, adjustment, workflow | Mechanism presence is not coordination success |
| Decision premises | Categories, rules, defaults, alternatives, and programmes | Rule, threshold, classification, automated determination, approval alternative | Technical transition is not necessarily judgement |
| Information processing | Creation, transfer, integration, aggregation, visibility, and signalling | Shared record, routed document, report, status, exception notification | Availability is not comprehension or use |
| Governance | Formal allocation of rights and intervention | Access restriction, decision scope, approval authority, escalation, segregation rule | Permission is not legitimate or real authority |
| Control | Standard, observation or comparison, and intervention or consequence | Validation, block, reconciliation, threshold, review, release | Rule, report, or status alone is incomplete control evidence |
| Accountability | Actor-forum relation involving explanation, judgement, and possible consequence | Assigned actor, trace, review forum, obligation, judgement, sanction | Traceability or approval alone is not accountability |
| Discretion | Bounded alternatives available to an actor or system | Configuration, extension, exception path, override | Absence of a rule is not evidence of discretion |
| Routine artefact | Representation that prescribes, cues, or records possible recurrent action | Test script, workflow, procedure, status, trace | Artefact is not ostensive understanding or performed routine |
| Material possibility | Candidate affordance or constraint arising from an arrangement | Required field, permission, workflow, automation, shared record | Feature availability is not perception or actualisation |
| Infrastructure relation | Embedded cross-setting dependency supported by standards or classifications | Master data, shared category, interface, release relation, installed-base dependency | Product scale is not infrastructure-in-use |
| Process architecture | Related events, activities, actors, objects, states, variants, and boundaries | Process ID, event, action, business object, state, gateway, exception | Model, script, or log is not the complete performed process |
