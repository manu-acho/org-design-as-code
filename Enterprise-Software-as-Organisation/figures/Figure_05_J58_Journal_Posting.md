# Figure 5. J58: submitting is not posting

![Two separately documented J58 routes. Direct posting records the journal entry without the illustrated verification workflow. In the verification route, submission leaves the entry unposted. Processor approval is expected to result in posting; rejection returns it to the requester to edit and resubmit.](Figure_05_J58_Journal_Posting.svg)

**Caption.** J58 documents direct journal posting (A) and verification before posting (B). In the verification route, submitting the entry does not post it. Approval is expected to lead to posting; rejection returns the entry with a reason and permits editing and resubmission. The contrast shows different represented allocations of work before the same type of accounting state, not actual segregation of duties.

**Text equivalent.**

- A. A general ledger accountant enters the journal data and posts it using the direct procedure.
- B. The requester submits an entry for verification. The entry is not yet posted. The processor approves or rejects. Approval is expected to result in a posted entry. Rejection returns the entry with a reason; the requester can edit and resubmit. This is a return path for an unposted entry, not a posting reversal.

**Provenance.** Original reconstruction of the Swiss J58 reference procedure. Panel A: J58-W08-01, PST 1–5. Panel B: J58-W08-05, VER requester 3–7 and APP processor 1–4; J58-W08-07, REJ 1–3 and EDT 3–4. See [Table 7](Table_07_Findings_Source_Locators.md). The figure does not infer that different people filled the represented roles, that a direct route circumvents a configured approval, or that a customer exercised either route.
