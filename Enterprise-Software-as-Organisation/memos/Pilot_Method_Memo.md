# Method Memo: Week 6 Pilot Coding

**Date / stage / affected IDs:** 8 November 2026; Week 6; EV2608CH-0002 to EV2608CH-0020 as listed in the private sampling frame

**Problem or ambiguity:** The codebook required testing against varied evidence while several initial records remained overview-level summaries.

**Options considered:** Delay all coding until every source page had been segmented; code all 26 initial records; or select a theoretically varied pilot and mark bundle-level limitations explicitly.

**Decision and rationale:** Select 15 records, five per process, covering normal progression, authority or control, exception or reversal, information or structure, and configuration or temporal organisation. This tests the full coding chain without treating the initial evidence log as a closed corpus.

**Consequences for prior coding:** No previous empirical coding exists. Evidence summaries remain unchanged. Full within-process coding must create narrower segments for high-value claims.

**Reproducibility action:** The private `PILOT_SAMPLE.md` records selection rationale; `Coding_Matrix_Pilot.csv` records all codes, interpretations, rivals, confidence, memo link, coder, and codebook version.

**Protocol/codebook version change:** Coding Manual version 1.0 adds EVENT, BUSINESS_OBJECT, OBJECT_STATE, PROCESS_BOUNDARY, CLASSIFICATION, TRACE_RECORD, EXTENSION, and GOV_ACCOUNTABILITY_SUPPORT.

## Pilot result

The codebook is usable for two-stage coding across the three domains, but source granularity is the main constraint. Normal-path and role or structural evidence can be described consistently. Authority, accountability, reciprocal coordination, and control effectiveness require more specific evidence than an overview table or role list supplies.

No pilot result supports a claim about customer configuration, enacted work, real authority, successful coordination, compliance, or organisational outcome.

## Gate decision

Week 6 passes with conditions:

1. use Codebook version 1.0 for Weeks 7 and 8;
2. segment evidence at page, step, branch, or object-state level before retaining high-confidence mechanism claims;
3. preserve the reference-architecture inference boundary;
