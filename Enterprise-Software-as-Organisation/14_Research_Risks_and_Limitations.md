# Research Risks and Limitations

| Risk | Severity and implication | Mitigation |
|---|---|---|
| Vendor-document bias | High: sources are normative, selective, and commercially authored | Triangulate artefact classes; analyse omission cautiously; label vendor claims; use negative cases |
| Intended versus enacted | Critical: documentary evidence cannot establish practice or outcome | Maintain three-level distinction in every claim; prohibit causal/outcome language; reserve field evidence for later papers |
| SAP specificity | High for generalisation | Treat as instrumental case; state edition/release; later platform comparison; generalise mechanisms analytically, not statistically |
| Technological determinism | Critical theoretical threat | Use capability/constraint language; document configuration and enactment boundary; engage practice/sociomaterial research |
| Coding subjectivity | Medium–high | Detailed rules, pilot, decision log, peer/dependent coding where available, rival interpretations |
| Release change | High operational threat | Freeze target release; capture date/version; retain superseded records; drift memos |
| Public access limitations | Medium–high: interactive/restricted content may create selective corpus | Log access and missingness; avoid claims from undocumented absence; seek stable official alternatives |
| Theory forcing | High | Descriptive-first coding; emergent-code quarantine; negative cases; theory-drop criteria |
| Confirmation bias | High given strong candidate proposition | Pre-register disconfirming searches; maintain rejection conditions; invite adversarial review |
| Overclaiming “organisation design” | High | Require consequence for differentiated work, information, authority, or control; exclude decorative/technical-only constructs |
| Configuration versus architecture | Medium–high | Record fixed/predefined/configurable/extensible status and configuration actor/lifecycle separately |
| Incomplete process models | High | Triangulate flow, test script, product help, roles, apps, configuration and exception sources |
| Copyright/licensing | Medium | Store metadata and permissible excerpts; do not republish protected SAP models; check institutional use |
| Researcher SAP familiarity | Variable: domain assumptions may enter coding | Write reflexive memos; preserve source language; seek SAP and organisation-theory review independently |

No mitigation eliminates these risks. The manuscript should explain how they delimit the knowledge claim: a reconstruction of reference architecture, not an evaluation of adopting organisations.
