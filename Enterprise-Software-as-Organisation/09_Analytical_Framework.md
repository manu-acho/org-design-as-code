# Analytical Framework

## From coded segments to findings

Analysis moves through five displays. First, a primitive ledger groups observations by construct and operation. Second, a dependency map links differentiated activities and classifies the relation. Third, a mechanism map attaches coordination, information, governance, and discretion mechanisms to each dependency. Fourth, a process configuration display identifies combinations, gaps, and exception paths. Fifth, a cross-process matrix tests recurrence, variation, and rival explanations.

## Within-process analysis

Construct a directed activity–object graph for each official solution process. Annotate edges with prerequisite, transfer, shared-resource, feedback, or authority relations. Then overlay primitives and mechanisms. Analyse normal path and exception path separately. Ask whether the apparent dominant coordination form changes at exceptions, whether information capacity matches the dependency, and where decision rights enter the sequence.

Summarise each process in a configuration statement of the form: `Within [bounded process], [dependency configuration] is addressed through [primitive configuration], combining [mechanisms], while discretion is located at [points] and constrained by [conditions].` Every term must link to evidence.

## Cross-process and multilevel analysis

Compare P2P, O2C, and R2R by theoretical dimensions rather than feature counts. A pattern is stronger when the same organisational operation is instantiated by different artefacts or when the same primitive performs different work under different dependencies. Micro findings concern primitive operations; meso findings concern process configurations; macro findings require replication across domains plus structural/cross-cutting artefacts.

Use set/configurational reasoning cautiously: identify recurring bundles without claiming causal sufficiency. Frequency supports prevalence in the corpus, not organisational importance. Critical controls or rights may appear once.

## Pattern tests

A candidate pattern needs: transparent scope; at least two independent supporting segments or a justified critical case; artefact-class triangulation where possible; an explicit mechanism; counter-evidence search; rival interpretation; and a confidence judgement. A candidate macro finding normally requires all three domains or a theoretically justified 2+1 contrast. Reject or narrow a pattern when contradictory evidence changes its mechanism, when it depends on an edition mismatch, or when it merely restates SAP terminology.

## Negative cases and rival interpretations

For each pattern search deliberately for: optionality where mandatory encoding was expected; human adjustment where standardisation was expected; system automation where approval authority was expected; local objects resisting integration; rights broader/narrower than process roles; and exceptions without encoded resolution. Test technical-necessity, regulatory-requirement, accounting-model, documentation-convention, and interface-convenience rivals. An organisational interpretation is retained when it explains a consequence for differentiation, dependency, information, legitimate action, or control beyond the technical description.

## Claim levels

- **Descriptive:** the artefact represents X. Requires direct evidence.
- **Interpretive:** X organises an actor/object relation in Y way. Requires an inference chain.
- **Theoretical:** the recurring configuration extends or bounds a theoretical construct. Requires cross-case/process pattern and rivals.
- **Prohibited from Paper 1:** organisations actually behave, perform, centralise, comply, or improve because of X.
